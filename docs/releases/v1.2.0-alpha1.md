# TechnicalEducationOS v1.2.0-alpha1

> **Alpha warning:** This release is for evaluation, integration, and controlled
> pilots. Validate every generated educational artifact before use. Schemas and
> public behavior may change before the beta.

## Overview

`v1.2.0-alpha1` is the first production-quality alpha of TechnicalEducationOS
(TEOS), a deterministic curriculum compiler. It completes the engineering
pipeline from registered curriculum and institutional inputs to validated,
scheduled, localized, themed educational documents.

## Major capabilities

- immutable curriculum records with JSON Schema and runtime validation;
- curriculum loading, compilation, dependency checks, and schedule resolution;
- Institution Profiles and Academic Calendars;
- administrative, instructor, and lab session renderers;
- Markdown, HTML, DOCX, and PDF generators;
- locale catalogs, themes, templates, and extension registries;
- deterministic build manifests, source hashes, trace metadata, and isolated
  output staging;
- public Python application API and `teos` command-line interface;
- maintained legacy week-record reproduction path;
- import/export boundaries and a compact Reference Curriculum; and
- unit, integration, end-to-end, regression, artifact, negative-input, and
  performance verification.

## Architecture

The structured curriculum model is authoritative:

```text
registered knowledge → approved blueprint → curriculum model
    → validation/compilation → scheduling → rendering → generation
```

Institution configuration controls schedule and presentation without owning
curriculum meaning. Templates control presentation only. Generated artifacts
are disposable and never become source records.

## Installation

The Python package version corresponding to this release is `1.2.0a1`.

```bash
python -m venv .venv
.venv/bin/python -m pip install technicaleducationos==1.2.0a1
.venv/bin/teos --version
```

Wheel and source distribution files attached to the GitHub release can also be
installed directly. See the [installation guide](../INSTALLATION.md).

## Minimal verification

With a source checkout:

```bash
teos build --course examples/reference_curriculum/curriculum
```

For the complete 96-artifact build, follow the
[End-to-End Reference Build](../END_TO_END_BUILD.md).

## Breaking changes and upgrade notes

This is the first public release, so there is no supported public version to
upgrade from. Relative to unpublished `0.1.0` development snapshots:

- the package reports `1.2.0a1`;
- canonical `build`, `schedule`, and `render` workflows supersede direct
  week-record generation;
- generated outputs are no longer stored as repository source;
- public application support is limited to names exported from `teos`; and
- inputs must comply with the frozen v2 schemas and documented repository
  structure.

The `generate`, `audit`, and `generate-administrative` CLI paths remain
available for approved legacy records but are deprecated.

## Known limitations

- This alpha supports CPython 3.11 and 3.12 only.
- The distribution contains application code, not an embedded curriculum or
  schema bundle; builds receive repository and schema paths explicitly.
- The v2 model has no explicit prerequisite/dependency-edge input field.
- Canonical session artifact types are administrative, instructor, and lab.
- Reference content is demonstrative and is not a complete program or a
  substitute for institutional, regulatory, or safety review.
- Alpha schemas and public behavior may change before beta; compatibility will
  be frozen through the beta release process.

## Roadmap

`v1.2.0-beta` focuses on external pilot feedback, diagnostics, compatibility,
accessibility, and defect remediation. `v1.2.0` establishes the stable
compatibility baseline. `v1.3` will prioritize maintainability and reviewed
interoperability work based on adopter evidence. See [ROADMAP.md](../../ROADMAP.md).

## Feedback and security

Use GitHub issues for reproducible defects and documentation problems. Follow
[SECURITY.md](../../SECURITY.md) for private vulnerability reporting. Include
the TEOS version, Python version, command or API configuration, diagnostic, and
minimal safe input needed to reproduce a problem.
